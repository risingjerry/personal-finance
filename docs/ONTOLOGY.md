# 财务本体（Ontology）

一笔钱在现实里只动一次，但会在好几个地方被看到：微信账单里一行，银行 App 里一行，手机上一条支付通知，购物 App 里一张订单。
pfin 把"看到的记录"和"真实发生的事"分开：**记录原样保存，事件只算一次钱**。

代码：`pfin/model.py`（词汇）、`pfin/resolve.py`（合并）、`pfin/rules.py`（归属）。

## 1. 一个例子

以虚构数据为例：2022-01-01 12:00，在微信里付了美团 ¥88.80，绑的是一张交行信用卡：

| 记录 | 来源 | 角色 |
|---|---|---|
| 美团 ¥88.80，支付方式"交通银行信用卡(5678)"，交易单号 …001 | 微信官方账单 | 通道：定金额、定对方 |
| 财付通-美团，消费，¥88.80 | 信用卡 App | 资金：证明从哪张卡扣 |
| 美团 ¥88.80 | 微信支付通知 | 信号：实时提醒 |

三条记录合成**一个消费事件**：钱从信用卡（负债账户）流向美团，经过微信支付。

## 2. 五种东西

| 东西 | 是什么 | 例子 |
|---|---|---|
| **账户** Account | 钱放在哪、欠在哪。资产（银行卡、零钱、余额）或负债（信用卡、花呗、月付、白条） | `bocom:1234`、`bocom-credit:5678`、`wechat`、`alipay`、`huabei` |
| **对方** Party | 钱给了谁、从谁来。各来源叫法不同（"财付通-美团" = "美团"） | 美团、某个人 |
| **事件** Event | 真实发生的一件事，钱只在这里算一次 | 消费、退款、转账、自己账户互转、收入 |
| **记录** Observation | 某个来源里的一条原始数据，原样保留，挂到事件上 | 上表三行 |
| **账本** Book | 事件归哪本账，再细到项目 | 个人、生意/某项目、投资 |

账户编号：`<机构>:<卡号后四位>`，或钱包名。同一张卡在银行 App、银行短信、通知里必须用同一个编号，否则对不上。

### 记录的统一字段（Record v1）

| 字段 | 说明 |
|---|---|
| `key` | 去重身份：来源 + 原始单号；没有单号时用它在原件里的位置 |
| `source` / `dataset` | 来源和数据集，如 `wechat` / `payments` |
| `layer` | `money` 算钱，`detail` 只补明细，`signal` 只是提醒 |
| `role` | `channel` 通道账本 / `funding` 资金账户 / `detail` 订单 / `signal` 通知短信 |
| `account` | 所属账户 |
| `at` / `has_time` | 带时区的时间，换算到报告时区；`has_time=false` 表示原件只有日期 |
| `amount` / `sign` | 金额永远是正数（Decimal）；`sign` 为 -1 出、+1 进、0 不计收支 |
| `counterparty` / `title` | 对方、买了什么，照原样 |
| `method` | 付款方式原文，如"零钱""交通银行信用卡(5678)" |
| `ids` | 能跨来源对号的单号：交易单号、商户单号、`taobao:<订单号>`、`wxtransfer:<转账号>` |
| `fields` | 规则可以检查的原始字段，如支付宝的 `merchant_order_no` |
| `evidence` | 证据强弱：`official_export` > `open_api` > `web` > `screen` > `notice` |

## 3. 事件类型与账本

| 类型 | 判定 | 算不算花销 |
|---|---|---|
| `purchase` 消费 | 付给商家 | 算 |
| `refund` 退款 | 商家退回 | 冲减 |
| `income` 收入 | 工资、利息、收款 | — |
| `p2p` 人与人 | 转账、红包、群收款 | 看账本归属 |
| `internal` 自己账户互转 | 还信用卡/花呗/月付、零钱提现、转余额宝、取现金、本人名下卡互转 | **不算** |
| `fee` 手续费 | 某笔交易的通道手续费，跟随那笔交易的账本 | 记在原交易的账本里 |

账本 `personal` / `business` / `investing`，可再细到项目（`business/项目名`）。归属由本人的规则决定（`docs/RULES.md`）：
逐笔覆盖 > 有顺序的规则 > 账户默认 > 个人。没有规则命中的消费和转账进"待确认"清单，等本人说一句是什么。

分期借款的还款按规则里的还款计划拆开：本金算 `internal`，利息单独记 `interest_out`（等额本息，按实际利率逐期算，合计分毫不差）。

## 4. 合并规则

按角色分四轮，前一轮建事件，后一轮往上挂：

1. **通道**：微信、支付宝等官方账单每行建一个事件。两个自己的账户之间的一笔钱（如个人号转工作号），两边各一行，合成一个 `internal` 事件；
   被退回的转账，退款行挂回原转账，净额 0。
2. **资金**：银行、信用卡、花呗、月付，挂到同金额、同方向、5 分钟内的事件上。微信那行写了"零钱"就不找银行；写了卡尾号就只找那张卡。
   挂不上的自己建事件（刷卡、银行转账、月付直接付）。
3. **信号**：通知、短信 5 分钟内挂上；转账卡片放宽到 1 小时（卡片是发出时间，账单是收款时间）。
   **某账户的账单还没导出到那天**（例如微信账单只导到上个月），那天的通知就自己当事件，之后导出了账单会自动换成账单。
   账单最后一笔之后一小时内的通知不自成事件（多半是那几笔的迟到提醒）。只有通知时，转账卡片的"已退回"会冲销原转账。
   银行卡的短信和通知不会挂到用微信零钱付的那笔上。
4. **明细**：订单 1 小时内挂上，有单号的先按单号。订单永远不单独算钱；
   有的平台订单要过几天才扣款（携程拿去花按入住出账，酒店也可能前台付）：这类订单往后找 7 天，但收款方必须是携程，
   或者和订单是同一类商家（订的酒店、在前台付给酒店）。拿去花本身是一个资金账户（消费、还款都有记录），每月还款算 `internal`。
   完成了的订单一笔付款也找不到、而且那天拿去花的记录覆盖不到时，订单自己当事件，账户记 `ctrip-naquhua:guess`（推测），待核对。

通用约束：
- 同一来源同一数据集的两条记录不会挂到同一事件（两次 6 元停车不会被合成一次）。
- 订单不会挂到"自己转自己"的事件上（先把钱转到另一个自己的账户、再付款时，订单挂付款那笔）。
- 一个事件里钱从一个自己的账户出、进另一个自己的账户，一律记 `internal`。

### 覆盖优先级

同一账户可能有几份账单：官方导出、网页工具、开放接口、读屏。数据集带 `priority`：
**高优先级的账单覆盖它自己的日期范围（按整天算），低优先级的只补范围之外的日子**。例如某账户的官方账单仅覆盖最近几个月，之前的日子由读屏账单补上；
另一个账户的官方账单未覆盖最新几天，之后由开放接口的余额流水补上。`pfin coverage` 列出每个账户由谁覆盖哪些日子。

## 5. 时间

所有事件换算到一个报告时区，写在私有 `config.json` 的 `timezone`（默认 `Asia/Shanghai`），改时区只改这一处。
不带时区的原始时间按来源自己的时区读（国内 App 默认北京时间），原始记录里的时间不改。

## 6. 已知的数据坑

| 坑 | 处理 |
|---|---|
| 微信零钱提现：账单 2002.00 含服务费 2.00，银行到账 2000 | 按备注里的服务费扣掉再比 |
| 支付宝免密扣款：下单比扣款早一天 | 用 `paid_at` |
| 同一笔微信转账有"发出""已收款"多张卡片 | 按转账号合成一条 |
| 转账卡片只有聊天 ID | 一次性从微信通讯录查名字，存私有 `contacts.json` |
| 已取消/关闭的订单、关闭且未付款的支付宝交易 | 不参与合并 |
| 场外交易对方常把金额凑整（1234.56 付成 1235） | 该数据集允许 1 元误差（`tolerance`） |
| 支付宝商户余额流水看不到用银行卡付的钱 | 优先级低于官方账单，只补账单之后的日子 |
| 手机读屏：同一列表里一模一样的两行是真的两笔 | 同一列表里第 n 次出现就算第 n 笔；同一列表读两遍仍只算一次（只有日期的列表也一样） |
| 交易所流水没有编号，几份导出时间段重叠 | 按内容去重，同一文件里一模一样的行仍算多笔 |
| 同一订单先后两次采集状态不同（未支付 → 已完成） | 以最后导入的那份为准 |

## 7. 不进合并的数据（消融）

`pfin sources` 列出每个数据集的角色和不进合并的原因，例如：被官方导出代替的读屏账单、月度对账单（不是交易）、
通知里的日报周报（不是钱的移动）、交易所数据（进投资账 `pfin invest`，不和付款记录合并）。

## 8. 投资账

`pfin invest` 按交易所和币种汇总资金流：充提、场外买卖、合约结果、资金费、手续费、理财收益、现货买卖。不估价：非稳定币按数量列出。
"结果" = 合约 + 资金费 + 手续费 + 理财，按美元稳定币计。场外买币若是给生意付款用，在付款侧由规则归到生意账。
